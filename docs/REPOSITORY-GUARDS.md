# 仓库产物护栏

本地提交、推送和 CI 分别检查，规则集中在根目录 `.repository-policy.json`。内容/历史护栏读取 Git 暂存对象或提交对象，识别真实字节，不执行被检查的特效源码；原有资产检查另行加载元数据和依赖。

## 自动启用

```sh
npm ci                     # prepare 自动安装 pre-commit / pre-push
npm run hooks:install      # 已安装依赖时重新启用
npm run repo:check:staged   # 检查实际暂存内容
npm run repo:check          # 检查 HEAD 及清理基线后的所有提交
npm run repo:test           # 实际 Git 提交/推送拦截测试
```

钩子仅写当前仓库的 Git 配置，记录执行安装时可用的 Node 路径，避免依赖失效的默认 Node。已有其他 hooksPath 时保留原配置并明确报错，需在已有钩子中接入本库检查或明确切换为 `.githooks`。包安装到其他项目和 CI 不改宿主 Git 配置。

## 三层检查

| 层 | 检查内容 | 拦截位置 |
| --- | --- | --- |
| pre-commit | 实际暂存 blob 的路径、内容格式、预算；随后检查资产元数据/依赖 | 创建提交之前 |
| pre-push | Git 提供的所有待推送引用；清理基线后的每个提交，包括合并侧枝；完整可达对象总量 | 发送远程更新之前 |
| CI `Repository source guard` | 完整历史复检及独立拦截测试；不依赖本地钩子 | 构建、部署之前 |

暂存了产物之后再改名、替换或删除工作区文件，不能改变将提交的 blob。历史中先加入产物再删除、或把带产物的侧枝合回，仍被推送检查拒绝。清理前的旧历史不能作为新分支重新推回。浅克隆缺少基线时明确拒绝检查，需补齐历史。

本地推送钩子还拒绝删除 `main` 或以非快进更新替换其历史，包括使用 `--force` 的情形。普通功能分支仍可正常整理提交，但每个待推送提交都须符合源码边界。提交中误删必需的规则、钩子或检查代码会被明确拦截。

## 保存边界和预算

- 只允许约定源码目录；唯一 HTML 入口为 `demo/index.html`。作品专用预览、交付、revisions、versions、raw-runs 等目录不能提交。
- GIF、视频、ZIP、其他压缩包、PDF、运行日志禁止入库；把二进制改成 `.js` 或 `.json` 也会按真实内容拒绝。
- 真实 PNG 原资源仅允许进入 `src/fx/<category>/_assets/`、公开资产例子和明确 PNG 测试 fixture；字体仅允许 `demo/fonts/*.woff2`。软链接、子模块和未解决的合并条目不作为资产源码入库。
- 普通源码文件上限 1 MiB，必要原资源单文件上限 4 MiB，单次提交的完整源码树上限 16 MiB。完整可达 Git 对象按未压缩体积计，默认上限 64 MiB；当前清理基线约 6 MiB。
- 独立测评只允许每项根目录的 Markdown 报告与 `build-summary.json`；单文件 64 KiB、单项 128 KiB、全部测评文字 512 KiB。调用、图像、各稿、完整构建清单留在 ignored records。

必要新资源或长期正常源码增长可以通过明确审阅的规则变更调整预算。不要为导出产物提高额度。规则不会自动删除手写作品；本地运行记录使用 `npm run assets:clean` 查看并按需清理。

## 被拦截后怎么恢复

1. 尚未提交：从暂存区撤出产物，例如 `git restore --staged -- records/`，保留本地文件并移入 ignored 输出目录。
2. 已提交但未推送：重做包含误提交的本地提交，或从干净基线重新应用源码改动。只在末端删除文件无法清除历史大对象。
3. 旧克隆：重新克隆已清理的远程，迁移必要源码，避免合入旧历史。基线身份是清理后的 `68d2b6d7c0ef06328d585bd62d88f066cb639b9b`。

## 远程强制边界

本地钩子可被有意绕过，CI 失败也不会自动从远程抹掉已经推入的对象。GitHub 管理员应将 `Repository source guard` 设为 `main` 的必须通过检查，并禁止强推/删除；本仓库不能通过普通源码文件替代服务端分支规则。当前会话只有可用的 SSH Git 访问，没有可用的 GitHub 管理 API 凭据，因此没有声称已设置服务端强制规则。

这轮只修改仓库维护门禁，不改变创作工具契约、素材算法、冻结版本或渲染行为。验收采用真实 Git 暂存/提交/合并/推送的隔离测试，避免为维护门禁产生额外作品和交付文件。
