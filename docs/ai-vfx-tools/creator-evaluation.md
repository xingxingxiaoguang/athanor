# 独立创作者验收规范

用于实质工具/SDK 功能波的验收。仓库 [AGENTS](../../AGENTS.md)保留正式要求；本文帮助组织一次实作。作品的用户审批与工具可用性验收分别进行。

## 何时启动

新功能或有创作后果的一组改动完成必要技术检查后，启动一个新独立上下文作者。小而确定的改善合并一波，不为每个微调重做完整任务；确认问题的修复可由原作者在新固定构建定向补测，原记录不改。

## 固定环境与阅读边界

隔离快照记录逐文件摘要和构建身份，包含被测未提交实现。作者可调用公开 tools/search/inspect、读公开 API/例子和经公开 inspect 获取的参考效果源码，编辑自己的普通 JS。

作者不读研发交接、工具/runtime/SDK 实现、实现测试、sources.json 或其他作者方案；operator inspect 不请求实现 source。开发者不通过解释内部实现帮助其过关。

## 一次有效实作

1. 给相关但原创的复杂效果任务，先写用途、尺度和待验证问题；不限定 DSL 或强迫套预设。
2. 实际观察原尺寸图像，至少做两类有意义的局部修改，并比较；记录真实观看形式。
3. 查询与任务相关的真实状态/事件，保留公开请求、原始错误及恢复步骤。身份与采样不能伪造。
4. 明确选择一个冻结 run，技术验证并导出同一版本；相关功能涉及历史、缺源重放、资产消费或入库时实际走通对应链路。
5. 保留坦诚报告。确认问题修复后另加补测记录，不把原失败改写成成功。

## 三个判断维度

| 维度 | 必须给出的具体依据 |
| --- | --- |
| 创意自由与帮助 | 哪种轮廓/材质/运动/关系可表达或受阻；实际用了什么成熟机制；艺术选择有没有被侵入 |
| 顺手程度 | 应由工具接管的重复工程、契约/诊断/恢复负担；区别于独特造型与构图的正常创作劳动 |
| 组合能力与改进 | 机制复用、流程和连续编辑怎样帮助完成具体难点；哪些结果尚未证明 |

测试通过、API 数量、少几行代码或一个复杂演示都不能代替这些判断。没有适当对照，不推断净省时、普遍美术优越或能力跃迁。人类 GUI 便利不作为主要门槛；原尺寸图像可直接通过图像工具观察。
