# AI 创作工具定义与数据契约

这是[产品全景](README.md)的目标契约。当前9工具已实现，正式`fx_reuse / fx_explore`待交付；本文包含完整目标参数，**未进入现行Schema的字段不能调用**。实际能力见[实施状态](implementation-status.md)，SDK见[公开API](authoring-api.md)，当前输入输出以[definitions.mjs](../../experiments/vfx-lab/definitions.mjs)为准。实施顺序见[交接工作包](HANDOFF.md#9-后续研发路线具体工作包与验收)，下一项为冻结动画交付。

## 1 接口组织原则

AI 使用普通代码编写作品，调用 SDK 完成细粒度计算，再调用工具取得资料、资产、运行与证据。SDK 的函数定义是工具界面的一部分，必须真实实现、可查询和可调用；不是把算法名字写进提示词后要求 AI 自行补齐。

CLI、MCP 和其他调用端共用定义。公开定义需要参数 schema、返回 schema、默认值、示例、错误和可用能力；资源型长文档按需读取。现有 `id` 等直接参数通过兼容适配进入下列统一目标结构，旧调用继续有效。

### 1.1 公共引用

```ts
type Target =
  | { id: string; options?: Record<string, unknown> }
  | { run: string };

type ResourceRef = {
  kind: "effect" | "technique" | "operator" | "component" | "asset" | "reference" | "run";
  id: string;
  revision?: string;
};

type SampleAt =
  | { times: number[]; clock: "effect" | "playback" }
  | { event: string; offsets: number[]; clock: "effect" | "playback" };
```

`Target` 两个分支互斥。`id` 指向当前作品，`run` 指向冻结作品与原运行设置。从 `run` 重放时使用保存的源码与资产；不暗中执行磁盘上的当前文件。显式修改场景、参数或采样会生成有父记录的新运行；改变作品参数也生成派生作品修订。

引用的版本在运行时解析并固定。文本标签用于阅读，稳定 ID 用于关联。资源文件同时记录内容摘要，路径移动不应导致旧运行误用同名新资产。

### 1.2 结果与诊断

常规结果形态如下，工具按职责补充少量字段：

```json
{
  "ok": true,
  "target": { "id": "draft/example", "revision": "example-revision", "run": "example-run" },
  "summary": "本次运行与上一版的主要变化或观察范围",
  "artifacts": [{ "kind": "contact", "ref": "example-artifact", "path": "/absolute/path/contact.png" }],
  "diagnostics": [],
  "detailRef": "example-detail",
  "next": [{ "tool": "fx_probe", "reason": "查看接触事件前后的主体轮廓" }]
}
```

示例中的 ID 是占位值。工具通过 MCP 返回可直接观察的图片内容或调用端支持的媒体引用，同时提供本地路径；不能只让 AI 猜测如何打开产物。无法提供动态媒体时返回带实际时间的原尺寸分段密集帧，并说明证据形式。媒体解码通过、已提供播放入口、作者实际播放与看过顺序帧分别记录，不据编码成功推断完成观看。宽横图不能是唯一原尺寸入口，应提供不会被宿主整体缩小的分段或单帧。

诊断包含 `code`、`severity`、目标层或参数路径、证据引用、实际与期望，以及修正入口。能定位到调用位置时再提供源码位置；仅凭空画面不能编造颜色错误的根因。

执行成功与检查通过分开：验证工具可以返回 `ok: true, passed: false`。请求或执行失败才返回 `ok: false`。常规返回保留身份、图像、主要诊断和入口；帧表、环境与完整依赖放入详情。精简不能截断重要错误或隐去验证范围。

### 1.3 明确能力而非猜测结构

检查结果声明 `capabilities`，例如整体渲染、颜色光分层、命名层、轨迹、modifier 单独诊断、中间字段、身体映射或冻结重放。旧模块没有声明某项能力时，对应请求返回 `CAPABILITY_UNSUPPORTED` 及可用替代，不返回空数据冒充成功。

### 1.4 主体、动作与输出边界的目标语义

这些是待实施的公共语义，具体字段名在对应工作包交付时进入Schema/API：

| 对象 | 目标约定 |
| --- | --- |
| 程序主体 | 可声明稳定ID、空间、变换、范围、深度和所需状态；同一状态驱动绘制/发射/观察，无需迁入particle或维护调试副本 |
| 动作与挂点 | 区分playback/effect时钟和停顿，人物/挂点/发射共享采样；姿态跳变不伪造有限连续速度 |
| 状态可信范围 | 区分作者声明、解析值与显式差分；记录速度/位置的已检范围，观察结果不自动证明动力学一致 |
| 输出边界 | 完整资产边界与允许出画的视口分开；裁切同时作用color/light，固定矩形/变换/策略和被裁范围 |
| 绘制层 | 只有真实登记的层才能隔离或关联诊断；像素不能反推出未知对象 |
| 生产记录 | 工具保存请求/原始错误/运行与分析引用；作者补意图、艺术判断和明确选版 |

## 2 fx_search

**职责：**找到与创作目标、表现机制或具体问题相关的对象。

输入：`query` 必填；`kinds` 可选，默认检索全部资源类型；`filters` 可按单次或循环、尺度、身体依赖、时间方式、可复用状态和已验证能力过滤；`limit` 默认 6；`cursor` 用于继续读取。

返回：资源引用、匹配原因、概述、预览引用、成熟度、可调用性和下一查询入口。主题检索与机制检索共存，语义标注的来源和版本可查询。

```json
{
  "query": "主体是一段连续厚头薄尾的冲击，尾迹延迟消失",
  "kinds": ["technique", "component", "effect"],
  "limit": 4
}
```

没有匹配时返回空结果和相邻概念，不自动塞入固定冰晶模板，也不编造一个已经存在的部件。

## 3 fx_inspect

**职责：**给 AI 精确的调用契约和判断适用性的依据。

输入：`ref: ResourceRef` 与首次读取参考的 `file` 路径二选一；`sections` 默认 `overview, contract, example`，可选 `source, dependencies, evidence, pitfalls, provenance`；旧 `id` 调用兼容为 effect 引用。

`file` 只读取调用方指定的本地资料，返回固定摘要的 reference 引用和解码能力，不修改来源文件。静图、动画、精灵表与视频的帧和时长按可用解码器处理；解码器不支持时明确报告，不能返回猜测的帧率。视觉机制的解释由 AI 在查看画面后给出，和工具量测分开保存。

返回随资源类型变化：

| 对象 | 关键返回 |
| --- | --- |
| 算子 | 函数签名、输入输出 schema、单位、坐标、时间域、默认值、异常与示例 |
| 部件 | 可替换部分、状态和依赖、公开参数、探测能力、隔离预览和来源 |
| 技法 | 表现目的、组合结构、选择点、反例和视觉证据 |
| 效果 | meta、入口、公开选项、事件、已登记部件、创作契约与参考 |
| 资产 | 数据类型、分辨率、轴点、空间、范围、周期、alpha 和采样约定 |
| 外部参考 | 原文件摘要、已知尺度、帧与持续时间、区域及标注；不承诺内部可编辑结构 |
| 运行 | 冻结身份、实际条件、产物、分析和可重放范围 |

对 `painter`、颜色或曲线的查询必须能从这个入口到达，不要求 AI 先读实现猜含义。作品自定义选项没有完整声明时，返回实际默认值并说明未知约束，不把推断当成严格类型。

## 4 fx_scaffold

**职责：**准备正常可编辑的创作文件与必要上下文。

输入：`name` 与简短 `brief` 必填；`template` 可选 `blank, pure, simulated, composition`；`question`、`styleProfile`、`components` 与 `fromRun` 可选。`fromRun` 用于将冻结作品恢复为新草稿，不能覆盖当前作品。

返回：新作品 ID、源码绝对路径、初始修订、创作记录、公开契约入口，以及已解析的部件引用。传入 `components` 表示作者已经选择组合对象；工具负责装配导入与明确的适配，不自行解释 brief 或发明艺术方向。

空白稿提供最小有效接口，作者决定内容。选择一个示例起点时返回其名称、已有内容与待改之处。无论使用哪种起点，不能把尚未编辑的示例称为根据意图完成的作品。

## 5 fx_reuse

**职责：**让参考中的局部成果以明确身份进入作品，或准备一次可审查的提取。

输入：`source: ResourceRef`、目标草稿 `targetId` 和 `mode` 必填；`selector` 只接受源中已登记的输出或有版本约束的候选片段；`bindings`、`bakeSettings` 和 `expectedRevision` 按模式提供。

| mode | 行为 | 返回 |
| --- | --- | --- |
| `link` | 引用固定版本的可执行部件或资产，生成适配入口 | 文件变更、依赖锁、绑定与隔离预览入口 |
| `copy` | 将有明确边界的部件复制为独立可编辑版本 | 新引用、来源记录、保留依赖与差异 |
| `bake` | 从已声明输出或明确渲染目标保存资产 | 图像、mask 或序列引用，烘焙条件与失去的可变性 |
| `prepare` | 为尚耦合的片段整理依赖、源边界和对照条件 | 提取候选与隔离验证要求，不承诺自动解耦 |

工具不修改来源，不覆盖同名目标文件；`expectedRevision` 不匹配时返回冲突。只有能构造有效部件时才返回 `materialized`，提取准备返回 `candidate`。

可复用对象应包括束流横截面/亮丝/头尾、蓄力收缩、岩石形状/分面/描边、刀光、裂纹与成熟烟材质。阶段组合以可展开普通代码呈现，允许重排和替换，不升级成固定招式DSL。例如只借用刀光机制时，应能指向头尾弧带部件并替换路径与材质。对于未模块化的原始刀光代码，先准备候选，由 AI 通过普通编辑形成新部件，再在隔离预览中比较迁移前后。

## 6 fx_render

**职责：**将作品变成有明确条件、可观察且不可变的运行。

输入：`target` 必填；`scenarioRef`、`sampling`、`views`、`note`、`detail` 和 `budget` 可选。

- `sampling` 声明输出帧率、时间窗口或稀疏时刻；同一请求不能含混地混用两种采样方式。
- `views` 选择原尺寸、放大、连续帧、动态、颜色、光或完整动作场景；实际支持范围由能力查询给出。
- `note` 记录本轮修改或艺术假设，内容可为空，不阻断快速试验。
- 从旧 `run` 改变场景或采样生成派生运行，保留其作品修订。改作品参数通过当前作品目标或 `fx_explore` 显式完成。
- 场景须固定动作时钟、挂点适配与输出边界；完整act、静态参照和作者自画人物分别声明，不能由一个actor布尔值含混替代。
- 事件窗口证据报告原生单格尺寸、请求/实际时间、网格与分段、帧顺序；纯保存图分析不产生艺术新版本，额外求值标明冻结来源。

返回：`run`、作品修订、来源摘要、实际参数与场景、时钟、采样覆盖、关键证据和清单。请求时间与实际模拟时间分别保存；渲染没有检查到画面时给出可操作诊断，但合法的空开头不自动判整件作品失败。

稀疏预览不能冒充完整导出序列。需要完整交付时，从冻结目标生成密集运行，再明确导出该新 run。所有渲染保留艺术像素分辨率，快速预览不能默默把作品先缩小再放大。

## 7 fx_probe

**职责：**让 AI 查看当前问题涉及的局部事实，避免改作品来调试。

当前可用子集如下。参数为`run/at/view/sampling/layers/particles/tracks/fields/limit/window`，clock仅effect，粒子选择使用字符串birth ID；精确互斥与枚举仍以Schema为准。

| 当前view | 来源与选择 | 边界 |
| --- | --- | --- |
| preview/color/light/combined | 单run保存图；at选择时间/事件 | 不推断内部层 |
| particles/trajectory | observe声明的Birth/State；layers/particles/fields | 真实声明属性或离散轨迹，非连续历史；默认前12个出生可能已不活跃 |
| sources | motion.observeSource；layers为source ID，fields选择状态 | 保存/冻结重放真实位置、速度、角速度与导数策略；不接受particles |
| contacts | contact.observe完整事件表；window默认[0,duration)，layers为组、particles为父ID | 不接受at/fields，查询真实事件时刻 |
| trails | trail.observe历史frame；at/layers/tracks | 完整采样点和time/simulationTime；不接受fields/particles/window |

程序主体、命名绘制层、任意mask/field、without修改器与playback时钟属于下述目标能力，尚未交付。目标还包括按请求时刻选择活跃对象、保留显式ID与省略说明，避免默认返回一组已死亡粒子。自画岩块没有声明就不能被自动发现，也不要求作者造不绘制的假粒子。

**以下为目标输入与返回，不是当前可直接调用的完整签名。**

输入：`run` 必填；`at: SampleAt`、`layers`、`particles`、显式登记主体的选择、`fields`、`view`、`without` 可选；`sampling` 可选 `saved` 或 `replay`，默认使用已有帧。

`view` 可以请求轮廓、去光、明暗、轨迹、中间场、mask、像素变化、层叠加、背景或动作等已支持视图。`fields` 可以请求位置、速度、年龄、透明度等已登记属性。`without` 仅接受已登记的层或修改器 ID，产生有标记的诊断变体。

返回：小规模属性表、局部图像、采样时刻、字段单位、支持范围和分析引用。作者声明的近似速度不冒称经过位置导数一致性验证；原尺寸图按可消费宽度分段，保留实际比例。使用保存帧时返回最近实际帧及误差；重放时使用冻结依赖，并保存分析条件。去掉修改器后的结果不能冒充原运行本身。

```json
{
  "run": "example-run",
  "at": { "event": "release", "offsets": [-0.1, 0, 0.1], "clock": "effect" },
  "layers": ["inward_sparks"],
  "particles": ["gather/40", "gather/41"],
  "fields": ["position", "velocity", "age01", "opacity"],
  "view": "trajectory",
  "sampling": "replay"
}
```

没有内部观测点的旧模块仍可做整件颜色、光和画面探测。不能从最终图像无损反推每个粒子的身份或未知中间场。

## 8 fx_compare

**职责：**按明确问题比较已保存的版本与条件。

已实现子集还支持兼容参数 `channel:preview|color|light|combined`，与 event/offsets 或 alignment:time/times 配合，直接观察保存通道；完整目标中的任意 views/场景意图尚未全部实现。

输入：`runs` 必填，2 至 4 个；`alignment` 显式选择共享事件、绝对时间或声明周期的相位；`offsets` 或 `times` 按对齐方式提供；`views`、显示尺度和场景比较意图可选。

返回：对照图或动态证据、每个样本请求与实际时刻、裁切或夹边情况、尺度与场景差异、可选像素量测。缺少命名事件就报告缺失，不猜测对应关系。重复夹到同一边界帧可以合并并说明。

目标支持围绕释放、退场、聚合等窗口输出原尺寸分段网格或实际可播放的局部对照；动态不可用时明确提供顺序密集帧。布局只改变观察包装，不能暗中重采样艺术图像或补造不存在帧。

默认按艺术像素与原点比较。需要按角色相对尺度比较时显式声明，标记缩放方式和原始尺度。比较不同背景、尺寸或帧率应显示条件差别，不能把全部差异归因于作品修改。

返回不包含自动美感排名。画面差异、轮廓覆盖、光量等量测是事实证据，是否更符合意图由创作者判断。

## 9 fx_explore

**职责：**执行作者指定的受控实验，降低对照成本。

输入二选一：

1. `baseRun` 与一至两个 `axes`，每个轴指向已声明公开参数或绑定的有限候选值。
2. 若涉及结构变化，传入作者已经编辑好的多个 `candidates` 作品目标。

另有 `question`、共同场景、采样和预算。默认最多 6 个变体，扩大数量需调用方显式指定预算。参数型变体从冻结源码生成派生作品修订与运行，不修改工作文件；结构型变体保留各自源码身份。

返回：候选运行、统一条件的对照、每个变体改动的因素、相关量测与成本。不自动生成新的艺术方向，不声称自动选出最好的一版。

实验问题可以是束头轮廓、退场包络、蓄势与释放节奏，或到达是否驱动主体增长。作者可替换结构候选，工具明确共同场景、时钟、种子、材料/参数及实际未隔离项；不把源码任意变化强称单因素实验。

随机种子变化可以检验分布稳定性，但仅换种子不能作为结构探索的证据。工具应说明实验改了什么；创作者负责实验是否能回答问题，以及最终选择。自定义代码无法保证局部变化的隔离时，返回实际差异和限制。

## 10 fx_validate

**职责：**验证明确目标的技术契约与作者声明的约束。

输入：`target` 必填；`profile`、检查项、种子、覆盖与预算可选。`profile` 可以声明结束方式、画布边界、调色板约束、循环、动作和资源预算；风格观察建议与硬性技术要求分开。

输出包含 `passed`、错误、诊断、未执行检查、目标身份、检查表示及覆盖。检查表示区分保存图像、冻结源码重放和静态契约，不能把一种通过推广为另一种也已验证。

| 检查 | 应明确的范围 |
| --- | --- |
| 复现与时钟 | 固定源码、资产、种子、时钟和共同样本；两个缓冲分别检查 |
| 越界与结束 | 资产边界/视口声明、时间点、通道、外边距、被裁范围与结束策略；有限采样不声称穷尽所有帧 |
| 循环 | 接缝附近图像与可观测运动；有意保持帧或跳变按声明处理 |
| 事件 | 身份、触发范围、重放与重复发射；不可观测的内部事件列为未检 |
| 场与图像 | 尺寸、空间、数值范围、alpha、采样和无效数据 |
| 角色与动作 | 挂点、映射、事件同步和该角色适配器支持的内容 |
| 性能 | 运行环境、场景、分辨率、时段与预算，不作跨设备绝对保证 |

边界诊断应定位越界时刻、通道、区域/所需范围；存在真实主体/层声明时再关联ID，不能从像素猜测责任对象。视口检查评估声明输出内的结果，完整资产检查保留外溢诊断。无意越界不能以关闭检查或任意裁切伪装修复；有意出画不应迫使作者包装底层写像素方法。

保留余烬或转交下一效果的作品，不因非空结束而一律失败。空画面诊断可以指向颜色契约等排查入口，不能在未取得调用证据时断定根因。技术通过不输出艺术通过字段。

## 11 fx_history

**职责：**让 AI 找回作品上下文与版本关系。

输入：`id`、`run`、关键词、分支、分页与需要的详情可选；至少指定一个查询范围。默认返回摘要。

返回：作品修订与运行树、修改假设、实验轴、观察与验证引用、选定版本记录、与当前文件的来源差异。没有决策记录时如实为空，不从最新时间自动推断“最终版”。

该工具负责查询。恢复旧作品通过 `fx_scaffold.fromRun` 创建新稿；重放通过 `fx_render.target.run`；导出直接指定旧 run。无需恢复整个 Git 工作区来复查一个旧效果。

## 12 fx_export

**职责：**交付一个明确选择的保存版本。当前只支持`run + validationRef`的图集交付；下述动画、代码与资产包是目标扩展，不能直接将format等字段传入现行工具。

目标输入：`run`必填；`format`选择实际已实现的图集、MP4、GIF、代码或资产包；输出布局、通道、编码/整数放大设置及`validationRef`按支持范围可选。能力查询应说明编码器可用性。没有run时不采用最近版本，编码器缺失/执行失败不返回成功媒体。

返回：产物、源run/digest、作品摘要、原点、实际帧表/帧率/时长、端点处理、事件、结束方式、色光混合、音轨及附带验证范围。媒体需记录所用通道、放大/填边/裁切、GIF调色与百分之一秒时基量化、MP4有损编码等事实。默认保留完整保存序列；作者显式选择抽帧时记录被选帧与新的时间安排。

导出消费保存图像与固定依赖，不执行当前稿。按manifest帧矩形从同一冻结图集解包，利用原库视频能力封装，不重新发明作品求值。稀疏保存帧不足时返回明确补采样请求，补成的新run需作者重新选择，不能暗渲当前文件或替换旧选择。

validationRef属于另一个run时拒绝关联；缺少验证则标未验证，不补造通过。完整场景和仅特效cutout分别声明，不能把含不透明地形/人物的输出宣传成纯VFX透明层。PNG/color与additive light是精确像素交付；combined普通alpha和媒体光合成说明近似。编码/全文件解码通过只证明技术可读，不证明作者已观看或美感达成。

引擎格式按实际支持列表提供，文件生成与目标引擎导入验证分开。原有atlas调用保持兼容，动画交付不要求作者写解包/编码脚本。

## 13 必须覆盖的错误与恢复

| 错误码 | 典型触发 | 返回中应提供的恢复信息 |
| --- | --- | --- |
| `INVALID_INPUT` | 字段类型、互斥目标或单位不符 | 参数路径、期望类型、最小正确示例 |
| `RESOURCE_NOT_FOUND` | 引用或事件不存在 | 已知候选与查询入口，不自动替换目标 |
| `REVISION_CONFLICT` | 当前作品与写入前提不符 | 当前与预期修订、涉及文件 |
| `CAPABILITY_UNSUPPORTED` | 未声明内部层、场或属性探测 | 实际能力和整体观察等替代方式 |
| `REPLAY_UNAVAILABLE` | 缺依赖或后端版本不可用 | 具体缺项、已有保存图像可完成的操作 |
| `CONTRACT_MISMATCH` | mask 空间、场单位或颜色类型混用 | 冲突两端及转换或重新采样入口 |
| `SAMPLING_INSUFFICIENT` | 稀疏预览用于完整导出 | 针对同一冻结作品的密集渲染参数 |
| `BUDGET_EXCEEDED` | 帧像素、模拟步或时间超限 | 已完成证据、消耗及可缩小的范围 |

错误不会自动削减粒子、缩短寿命、改变采样或替作者选择作品。恢复操作仍能从返回的具体引用接续，不要求 AI 重新描述整件作品。

## 14 工作流如何减少调用负担

普通创作可用 `search → inspect → scaffold → render → compare → validate → export`，通过正常代码编辑完成改稿。需要局部机制时加入 `reuse`，定位问题时加入 `probe`，对照多个已选方向时加入 `explore`，中断后通过 `history` 恢复上下文。

调用和原始错误、分析/导出引用由公共记录机制关联；创作者只补意图、判断和明确选择。记录深度按任务需要，不因每次看图都强制生成完整快照或长报告。

例如一次局部修改可以只需要：改一条公开曲线，渲染新 run，比较旧新两个 run 的释放窗口，再验证选中版本。查询签名、中间资产、诊断和历史不是每轮必走流程。产品应测量这些入口是否减少重复实现与排错，而不是以调用次数越多或记录越完整作为成功指标。
