# Spine Particle 基础创作能力与 AI 工具设计

调研对象：[天生牛马 Spine Particle](https://tsnm-spine-particle.com/)，作者二两。观察日期：2026-11-05。

这个项目最有价值的参考，是把特效拆成可以反复组合的发射、属性、运动、材质和轨迹机制。Athanor 已经有不少相应的数学与绘制函数，但实验工具还没有把这些能力组织成 AI 容易发现、正确组合和局部修改的创作接口。继续增加渲染与导出功能，不能替代这一层设计。

建议吸收它的能力分解方式，建立可组合的代码算子和明确的数据约定。AI 继续通过普通代码创作；工具承担采样、插值、求解、像素处理和诊断。面板、拖拽、快捷键以及 Spine 文件兼容逻辑分别处理，不进入基础创作模型。

## 代码实现中值得吸收的机制

### 配置分解有价值 大对象和条件耦合需要重新设计

该构建的 `Ul` 生成粒子系统默认配置，`Su` 生成嵌套的光带配置。发射模式、发射形状、生命周期曲线、修改器、资源列表与时间轴关键帧都可分别辨认。运行时再从配置生成粒子状态，区分初始值、随机偏移、当前值、年龄和轨迹。

但这些概念仍装在一个大型对象中，部分组合依赖分支约定。例如出生函数 `jl` 会把 `inward` 与多种边界模式一起送进边界采样分支；选择“向内”也会影响出生位置。不能把所有 UI 选项理解成已经完全正交的原语。

AI 的组合应能分别表达：从圆盘内部出生、朝目标运动；从圆周出生、沿切线运动；从任意路径出生、朝固定方向运动。位置分布和方向策略不应互相暗改。

面板还把持续发射的最短时间描述为 10 帧，并提供生命约束与发射上限。这些产品取舍不应直接变成像素创作限制：一两帧的闪光和寿命长于发射窗口的余烬都有用途。接口应支持这些时间关系，另以可配置预算控制运行成本。

### 随机性既要复现 也要支持局部修改

`vv` 混合种子和索引，`hf` 产生可重复的伪随机序列。出生采样使用系统种子、发射批次和粒子索引；固定批次的探测得到相同序列，改变批次则改变结果。

这个设计支持复现，但不等于“修改颜色后运动一定保持原样”。出生过程顺序抽取位置、寿命、颜色、资源等随机值；启用一个额外随机属性可能改变后续抽样位置，发射批次又与更新方式有关。

AI 频繁做局部修改，应该提供按 `effect/layer/particle/channel` 派生的稳定随机通道，如 `position`、`lifetime`、`color`。新增颜色随机性不扰动已有轨迹；保持粒子编号时增加数量尽量保留原有样本。需要相关性时，由作者显式共享随机变量，例如“大碎块更慢且寿命更长”。

### 至少区分三种时间 与一类空间参数

该构建中，`Zc` 按场景帧求系统关键帧，粒子更新再用 `age / lifetime` 求生命周期曲线，光带还按自己的周期和错开时间求值。这些是不同的时间域。

面向 AI 应明确：

| 域 | 示例 | 常见误用 |
| --- | --- | --- |
| 场景时间 `t` | 0.30 秒爆发，0.60 秒开始退场 | 改粒子寿命后整场事件也被拉长 |
| 发射器局部时间 `τ` | 发射器启动后的第 0.1 秒 | 各系统不得不手动减起播时间 |
| 粒子归一化年龄 `u` | 生命前 20% 膨胀，后 40% 淡出 | 把全场淡出误写成每粒子淡出 |
| 路径归一化距离 `s` | 尾端变细，贴图沿带滚动 | 把空间锥度误当生命周期尺寸 |

曲线输入要标明绑定到哪个域；输出要说明是像素、透明度、倍率、角度还是速度。作者可以选择共用曲线，但共享必须是可见的关系。

### 曲线不只是画几个点 插值语义会影响作品

生命周期求值函数 `ul` 先排序和夹住输入区间；线性模式做线性插值，默认多点模式用相邻点估计斜率的三次 Hermite 插值。它不是一个可以任意指定四个控制量的通用贝塞尔求解器。

探测曲线 `(0,0)、(0.1,1)、(0.9,0)、(1,0)` 时，默认插值最低约为 `-0.00823`，`u=0.95` 时约为 `-0.00694`；线性模式该处为零。这只证明该数值函数可以越过控制点范围。不同绑定处的夹值逻辑不同，不能据此直接断言某个可见效果发生了故障。

AI 接口应显式区分线性、保持、平滑和允许回弹的插值；给透明度等受限属性提供范围诊断。尺寸或轨迹确实可能需要超调，不应全局强制夹值。曲线值直接使用作品单位，避免把 UI 中归一化的高度再隐式乘 5 或乘 360。

### 运动控制包含物理与艺术引导

普通粒子的更新路径先处理重力和风、速度衰减、径向与切向加速，再加周期扰动、速度曲线、位置更新和后续约束。径向方向来自粒子相对发射器的方向，切向则取其垂线。

黑洞控制进一步混合启动延迟、接近过程、横向速度抑制、路径位置混合和到达销毁。它有明确的视觉目的，不是单一的万有引力公式。

建议把运动能力组织成可检查的四类：

1. `acceleration` 改变速度，例如重力、径向和切向力。
2. `velocity` 控制实际移动速度，例如速度包络或方向场。
3. `offset` 叠加不积累漂移的位置扰动。
4. `constraint` 引导或覆盖位置，例如沿路径、贴面或吸向目标。

同一层使用几个修改器及其顺序，由创作者决定。工具负责执行、单位转换和冲突诊断，并能展示修改器前后的轨迹。碰撞保留反弹、摩擦、障碍或容器、接触事件等语义；“钢铁”“布料”作为公开参数的配方，而不是不可修改的材质黑箱。

### 路径采样应成为独立公共能力

`bv` 把折线或曲线离散为线段，记录长度、累计长度和方向；`Du` 缓存结果；`Tu` 按弧长随机采样；`Lo` 按进度查询位置。自动平滑使用 Catmull–Rom，存在手柄时使用三次贝塞尔。

对长度分别为 10 和 100 的两段直线，`Lo` 的 `uniform` 分支产生四次相等的 `27.5` 位移；另一分支按段参数推进，得到 `5、5、50、50`。因此 AI 接口应直接使用“按弧长”与“按段参数”这样的可验证语义，不依靠容易误读的面板标签。

路径查询还应返回切线、法线和距离，用于朝向、沿边发射、偏移和条带宽度。误差容忍度、开放端点、闭合接缝与退化段由工具处理。不能默认所有闭合形状都有唯一的“向外”方向，复杂形状需要明确法线约定。

### 常驻循环值得单独建模

常驻粒子没有简单照搬“无限寿命的普通粒子”。其位置、尺寸、透明度和旋转通过种子相位与整数谐波计算，在给定周期内重复。独立光带也具有按绝对时间求值的路径与星屑计算逻辑。

这种方式便于任意时刻采样，能避免某些循环被历史状态拖累。但不能据此宣称所有旋转和所有配置都已保证无缝，也不能把有碰撞的状态模拟强行改成时间函数。

我们的算子应同时支持解析求值和固定步长模拟：无碰撞的弹道、周期摆动、程序化路径优先直接求值；碰撞与依赖历史的行为使用固定步长及可重放状态。

### 拖尾与独立光带共享几何基础 但语义不同

粒子拖尾记录运动历史，超过最小距离才增加点并限制保留数量。独立光带 `Kl` 则用程序路径生成当前可见片段，支持向内、向外和波动等形态，并从带上派生星屑。

光带绘制按切线构造法线，向两侧扩出宽度；自定义贴图通过三角形裁剪和仿射映射绘制，默认外层和内核使用不同宽度与透明度。UV 滚动改变材质采样，几何不必随之移动。

适合像素的公共层应保留“中心线、宽度、沿线颜色、可见区间、材质采样”这些输入。历史拖尾还需明确长度以秒、距离还是点数表示，以及粒子死亡后是否继续消散。像素后端可以直接栅格化条带，无须先创建 Spine 骨骼。

### 噪声 发光和图像处理的覆盖有限

普通粒子的噪声路径主要叠加多频正弦与余弦，用种子区分相位；在指定周期下使用整数频率帮助重复。独立光带也叠加周期波形。因此这里的“湍流”不能直接解释成空间连续、可平铺、可求旋度的通用噪声场。

光斑使用缓存的径向渐变，光带使用内外层与混合模式。值得吸收的是亮核、外缘、透明度和几何宽度可以独立控制；它没有提供我们需要的完整像素光照模型。

资源系统重点在上传、序列帧、着色、轴点和混合，代码还保留基础程序形状与默认渐变纹理。PNG 输出路径有缩放、RGB 与 alpha 通道处理。没有在已检查界面及相关实现路径中确认通用的消融、图像平流、抖动或程序纹理算子链；不能把 UV 滚动和普通图片缩放算作这套能力已经齐备。

### 预览和交付应共用求值内核

该构建存在分别处理实时预览、跳转重算和烘焙的路径。实时预览用受上限约束的实际时间增量，跳转路径按预览帧率重算，骨骼烘焙也有按输出帧率推进的路径；相似运动逻辑在多处出现。

这是预览、跳转和不同导出频率可能产生差异的实现风险。本次没有用同一配置逐帧比对三条路径，不能把风险写成已复现的视觉缺陷。

我们应让预览、探测和输出复用一个求值器，输出帧率只决定采样时间。预热、循环、结束和关键帧压缩由输出工具承担。其 `ff` 压缩函数按同一时刻的插值位置误差递归保留采样点，探测中将 11 个直线点减到 2 个，并在给定容差下保留突变峰值。这类技术负担值得交给工具，但像素输出还应检查栅格化后的误差，不能只看连续坐标误差。

## 面向 Athanor 的基础能力设计建议

以下是待实现的接口设计，不是目前已经存在的工具。

### 用代码算子承载细粒度能力

不建议把每个按钮变成 MCP 工具，也不要求 AI 为每个粒子、每个像素或每个属性发起一次工具调用。基础能力以可导入、可组合的代码算子为主，继续兼容现有 `draw` 和 `create`；需要保存和交付的配置可采用声明式片段，但不强迫所有创作改写成大型 JSON 图。

| 算子族 | 输入与输出约定 | 工具承担的工作 |
| --- | --- | --- |
| `domain` | 几何域或 mask → 采样器 → 位置、切线、法线、权重 | 面积与边界采样、非均匀密度、退化处理 |
| `schedule` | 事件、区间、数量或速率 → 具稳定身份的出生记录 | 持续与爆发排期、分数累积、错开、距离发射 |
| `random` | 种子、稳定 ID、具名通道、分布 → 属性样本 | 复现、通道隔离、显式相关采样 |
| `curve` | 时间域、节点、插值、输出单位 → 数值或色带 | 插值、边界、超调诊断、时间映射 |
| `motion` | 出生状态、加速度或约束、求解约定 → 轨迹或状态 | 弹道、阻力、场、路径、碰撞、到达事件 |
| `path` | 几何定义、闭合与误差要求 → 可查询路径 | 弧长、切线、法线、重采样、接缝处理 |
| `field` | 坐标域、种子、频率、范围、周期 → 标量或向量场 | 噪声、分形、周期场、梯度及向量运算 |
| `image` | 图像或 mask、场、参数 → 图像及可复用中间结果 | 程序形状、位移、消融、抖动、轮廓、缩放 |
| `material` | 图像、色带、透明方式、像素规则 → 采样结果 | 序列帧、轴点、调色、透明与材质采样 |
| `trail` | 历史或程序路径片段、宽度与材质 → 条带 | 采样、宽度变化、裁切、端点和消散 |
| `light` | 来源 mask 或几何、颜色、半径和强度 → 光层 | 核心与外光、生命周期绑定、可选像素化 |
| `compose` | 以上结果、变换、事件和层关系 → 作品 | 坐标变换、前后层、共享事件、依赖与缓存 |

算子输出需要携带必要语义。路径注明坐标域；场注明标量范围或向量单位；图片注明分辨率、轴点和 alpha 约定；曲线注明输入域和输出单位。错误应指出具体层与属性，并给出可执行的修正建议，而不是返回一整页配置。

下面三个概念契约说明接口应具体到什么程度，名称和结构仍待实现验证：

```text
domain.sample({
  domain, measure: "area" | "boundary", count,
  densityField?, seed, channel, space
}) -> [{ id, positionPx, tangent?, normal?, weight }]

curve.scalar({
  input: "scene.seconds" | "emitter.seconds" | "particle.age01",
  points, interpolation: "linear" | "hold" | "smooth" | "bezier",
  outputUnit, extrapolation, limits?, overshootPolicy
}) -> 可在指定时间上下文求值的曲线

image.dissolve({
  image, field01, threshold01, edgeBand01,
  previousKeepMask?, previousTime?, time, space, sampling
}) -> { image, keepMask, edgeMask, removedMask?, interval? }
```

`domain.sample` 的位置不隐含速度方向，未定义的法线也不伪造为“向外”。曲线的贝塞尔模式需要控制量，平滑模式需要明确斜率规则。消融的 `edgeBand01` 是场值带宽，不冒充固定像素宽度；固定像素轮廓由 mask 距离算子处理。只有传入前次保留区域和时间时才返回变化区域，并标注时间区间；随机跳帧得到的是该区间的变化，不能当作一帧的发射事件。

这些应是真正实现并可调用的能力。不能只提供名字和提示词，再让 AI 手写采样、插值和逐像素循环来补足。

### 图像能力需要专门设计

这部分不能从网站直接照搬，应结合 Athanor 的像素实现提炼。

| 能力 | 建议的明确语义 | 创作者保留的选择 |
| --- | --- | --- |
| 程序贴图 | 形状或距离场、噪声、调色板、像素尺寸 → 图像和 mask | 轮廓、明暗组织、材质特征和非对称细节 |
| 图像流动 | 区分 UV 平移、位移变形、向量场平流；声明边界和采样方式 | 流向、强弱分布、是否保持体积及何处断裂 |
| 消融 | 标量场与阈值 → 保留 mask、边缘 mask、当步被移除区域 | 消失方向、先后关系、边缘厚度和附属碎屑 |
| 抖动透明 | alpha 转有序或其他明确的覆盖模式，声明锁定坐标域 | 图案、颗粒尺度、是否允许随时间变化 |
| 半透明 | 保持 RGBA、颜色和光分别处理，明确混合方式 | 哪些材质用软透明，哪些保留硬像素 |
| 缩放 | 区分资产重采样、作品坐标缩放与最终展示放大 | 是否允许重新设计像素簇与线宽 |
| mask 运算 | 膨胀、腐蚀、描边、布尔组合和距离查询 | 轮廓语言和侵蚀方式 |

消融返回边缘与当步变化区域，便能继续驱动发光和粒子发射；场也能同时驱动图像和运动。这样创作者不必在每个效果中重新扫描像素并维护重复状态。算子需要明确纯函数求值与跨时间差分的区别，随机跳帧不能误把整个历史消融区域当成当步事件。

### 适合 AI 的工具定义应帮助发现和检查这些能力

七个现有工作流工具继续保留。基础算子不需要全部变成新 MCP 方法；可先增加少量入口或扩展现有入口：

- **能力查询**：按任务查询算子及组合示例，返回签名、单位、时间和坐标约定、可用后端、限制、相关算子。例如查询“向内汇聚”时，同时给出边界采样、朝向目标、吸引场和路径约束，说明差别。
- **构建诊断**：对作品代码及算子描述运行检查，返回依赖、实际生效参数、绑定关系和冲突。普通创作文件仍由 AI 编辑，不额外造一套文件编辑协议。
- **定点探测**：对保存版本按层、粒子 ID、时刻和修改器请求轨迹、属性值和局部图像。返回小规模数据与图片，支持临时单独查看某层或跳过某个修改器，无须作者改源码加入调试分支。

例如定点探测可以接受如下概念输入：

```json
{
  "run": "saved-run-id",
  "layer": "inward_sparks",
  "times": [0.1, 0.2, 0.3],
  "particles": [3, 7],
  "inspect": ["position", "velocity", "age01", "opacity", "light"],
  "compareWithout": ["motion.attractor"]
}
```

结果应标注真实采样时刻、属性单位与修改器名称，并附轨迹叠加图。跳过某个修改器产生的是诊断变体，不能冒充原始保存版本。`fx_validate` 对保存版本的绑定和 `fx_compare` 的采样窗口也需要随之完善。

### 不要把通用性理解为无限参数面板

一个共享几何域可以驱动发射，也可以生成 mask；一条曲线可以绑定尺寸，也可以绑定光强；一个场可以驱动消融，也可以派生运动。通用性主要来自类型、语义和组合，不来自把全部特效装进一个巨型配置对象。

常见组合可以有配方，如“短促爆发”“沿路径推进并脱落星屑”。配方应展开为普通算子和参数，允许替换任意部分。自定义粒子初始化、轨迹函数和像素绘制必须有普通代码扩展点；工具仍为这些代码提供一致的时钟、种子、缓冲和验证入口。

## 工具与创作者的职责

| 工具应承担 | 创作者应决定 |
| --- | --- |
| 采样、插值、积分、重采样、碰撞响应和像素循环 | 主体轮廓、重心、动势、节奏、材质语言 |
| 单位、时钟、种子、变换、alpha 与颜色光层约定 | 何时写实、何时夸张；何处需要不对称和意外 |
| 缓存、中间结果、差分区域、预热、重放与导出 | 哪些层存在，各层如何服务主视觉 |
| 技术检查、局部探测、版本对比和证据保存 | 问题是否值得修改，哪一版更符合意图 |
| 可展开且可修改的常用配方 | 新的结构、运动规则及超出既有算子的自定义表达 |

曲线、噪声和贴图算法可以交给工具；曲线的形状、噪声出现的位置和贴图要表现的材质仍属于创作。工具应提示“光层超出画布”或“曲线越界”，不应自动决定“亮度太高所以降低”或用审美分数覆盖作者判断。

## 下一轮应如何验证

先验证两条创作链，而不是扩建一整套编辑器。

1. **发射与运动链**：几何域、排期、随机初始属性、生命周期曲线、运动、简单轨迹和颜色光层共用约定。
2. **图像与场链**：程序 mask、已有噪声、消融、边缘和变化区域、抖动或软透明、衍生粒子共用中间结果。

用一个明确而可局部修改的创作任务连接两条链：例如 72×72 像素内，火屑从非对称边界内收，在 0.30 秒接触并闪亮一帧，随后灰壳沿纹理消融，边缘释放少量外扩碎屑。轮廓和节奏由创作者设计，工具提供实现机制。

这不是已经完成的作品或测评。实施后应让不读实现的创作者仅使用算子文档、工具定义和正常代码编辑完成以下修改：

- 保留运动，只改变消融方式和边缘发光。
- 保留贴图、节奏和随机个体，只改变出生域与汇聚轨迹。
- 保留主体，只改变拖尾长度和粒子死亡后的消散。

验证时记录创作者是否需要重写采样、曲线、轨迹历史或像素扫描；一次局部修改影响了哪些其他层；出错时能否从探测结果定位；能否从同一保存版本检查和导出。代码行数、调用次数、耗时可作为成本证据，但不能单独代表表达能力。

合格标准是：工具减少重复实现与排错，创作者仍能改变结构、运动和材质；创作、观察、提出修改假设、修改和再次验证能持续闭环。工程运行成功本身仍不构成创作工具好用的证据。
